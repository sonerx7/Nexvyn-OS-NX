# Release notes / Changelog

## [1.3.28-beta.2] - 2026-11-19

### Fixes in-OS beta install

- The updater accepts a pre-release build after installing it: 1.3.28-beta.1 reported `1.3.28` while its tag was `v1.3.28-beta.1`, so the placed file was taken for a wrong build and the backup was restored. The build now carries the full version (`1.3.28-beta.2`), and a release-only build matches its pre-release tag.
- Update offers follow version order: pre-releases sort by numeric identifiers (`beta.2` < `beta.10`) and come before their final release; a beta user is offered later betas and the final, a final user never an older beta.
- A failed install for a version mismatch shows its own message (`settings.upd_err_version`) in eight languages.

## [1.3.28] - 2026-11-18

### Smoother desktop and bulk installs

- A focused or hovered window that is idle is redrawn only when focus, text input or the pointer changes (`perf.focusIdle`, default on; `false` restores the old behaviour).
- The system widget reports CPU and GPU load against the current frame rate instead of showing 100% while idle.
- Installing several packages together paces the main-thread commits and retries a briefly locked app folder without blocking frames; the old version stays in place until the new one loads.
- The SDK ships an AI starter pack with recipes and golden projects for script, network, 2D game and native apps.

## [1.3.16] — 2026-11-15

### Switch Native TLS Backend, SSL Handshake & Public Certs Fix
- **Native Switch TLS / SSL Handshake (`source/core/net.cpp`):** Fixed persistent `"Secure connection failed / SSL connect error"` on console hardware. devkitPro's `switch-curl` routes through Horizon OS's native `ssl:` sysmodule (`libnx.c`). Because Horizon OS only trusts system internal CAs and fails when importing Mozilla root bundles (> 71 cert limit), peer/host verification is now disabled on Switch (`CURLOPT_SSL_VERIFYPEER = 0L`, `CURLOPT_SSL_VERIFYHOST = 0L`), ALPN/NPN negotiation is disabled (`CURLOPT_SSL_ENABLE_ALPN = 0L`), and external CA bundle parsing is omitted on Switch, enabling native encrypted TLS connections to all public internet HTTPS endpoints.
- **Network Fallback & Error Recovery (`source/core/net.cpp`):** Expanded automated fallback retry to intercept `CURLE_PEER_FAILED_VERIFICATION`, `CURLE_SSL_CACERT`, `CURLE_SSL_CACERT_BADFILE`, `CURLE_SSL_CERTPROBLEM`, and `CURLE_SSL_CONNECT_ERROR`, immediately recovering on a fresh HTTP/1.1 socket.
- **Default Search Engine & Migration (`source/apps/app_browser.cpp`):** Defaulted to DuckDuckGo to prevent Google SearchGuard challenge blocks.
- **CSS Cascade & Dropdown Menus (`source/web/web_css.cpp`):** Corrected percentage-based top offsets (`top: 100%!important`), restoring Semantic UI dropdown menus (e.g. video source alternatives).

### System resilience and app lifecycle (65)

- An uncaught C++ exception in an app (e.g. `std::stoi` invalid argument, `vector::at` out of range, out of memory) now only closes that app's window; Nexvyn OS continues running.
- A memory error in app code (null pointer, etc.) is isolated once per session: the window closes, the system stays up, and the user is advised to restart soon (`system.crashIsolation` setting, default on).
- An alert stating "“X” quit unexpectedly" appears for the terminated app, with error message and Reopen / Show Report / OK buttons.
- A detailed report is saved to the System/Logs/Crashes folder for each isolated crash.
- An app that crashes three times in the same session will not reopen; an alert is shown explaining the reason and advising the user to restart Nexvyn OS.
- Background services (alarms, reminders, automation, etc.) also run protected: a failing service is stopped for that session and a notification is displayed, preventing the system from crashing on every frame.
- App object instantiation, `onOpen`, `onLowMemory`, `canClose`, `onClose`, and destructor calls are also covered by the same protection.
- Mouse and touch events now also include the app name in the crash report (previously only keyboard and update calls were named).
- The crash log now includes the version, application ID, uptime, memory usage, registers, in-code addresses (for addr2line), and the call stack extracted from the frame pointer.
- The last 50 log lines are appended to the end of the crash log; these lines are kept in a fixed buffer without using the heap, allowing them to be written even with corrupted memory.
- In unhandled C++ exceptions (`std::terminate`), the log also writes the exception type and message.
- On boot following a crash, a "Nexvyn OS closed unexpectedly" window appears: Reopen / Show Report / Ignore.
- Crash reports are named with the date and time and stored in the System/Logs/Crashes folder; the latest 10 reports are kept.
- Thanks to the session flag (Logs/session.lock), sessions that ended without leaving a log (power outage, forced shutdown) are also detected, and an "improper shutdown" notification is displayed.
- After two consecutive crashes, Nexvyn OS boots into Safe Mode.
- If ZL + ZR are held down during boot, Nexvyn OS boots into Safe Mode.
- In Safe Mode, login items do not open, windows are not restored, and automations do not run.
- An orange "Safe Mode" badge appears at the top of the screen; tapping it displays options: Exit Safe Mode / Stay in Safe Mode / Turn Off System Updates.
- Upon exiting Safe Mode, skipped login items and windows open immediately without requiring a restart.
- A crashed application is not automatically reopened on the next boot, neither via login items nor via window restoration.
- If the settings file is unreadable, its last intact copy (settings.json.bak) is restored; user settings do not revert to defaults.
- A separate watchdog thread notes which application is running if the main loop does not progress for 10 seconds; if the system recovers, the note is deleted and how long it stalled is logged.
- If a frozen session was force-closed, a "The system became unresponsive while running 'X'" warning is shown on the next boot, and that application is not automatically opened.

### Saving, sleep, and resume in document and media apps (30)

- An unsaved (untitled) document is written as a draft during auto-save to the app's Library/Caches/<app>/drafts folder; this draft remains when Nexvyn OS crashes, the console powers off, or it is closed from the HOME menu.
- On its next launch, starting with an empty window, the app asks "Restore unsaved document?"; Restore opens the document as an untitled document marked "Edited", Discard deletes the draft.
- The restored draft remains that window's draft until the document is saved or closed, and is updated in subsequent auto-saves; a second window does not suggest the same draft.
- The draft is deleted when the document is saved to a file, closed choosing "Don't Save", or completely emptied.
- When Nexvyn OS closes without asking (closing from the HOME menu), drafts of unsaved documents that are still open are not deleted; they are offered again when the session is restored.
- Text Editor: a document with an associated file is silently saved during auto-save (via the same path as Ctrl+S, without prompts); an untitled or read-only document is written to a recovery draft.
- Text Editor: only documents with actual content enter the unsaved work list upon closing; when returning to Nexvyn OS, it immediately checks whether the file was modified externally (FTP, MTP).
- Code: tabs with an associated file are saved during auto-save, each untitled tab maintains its own recovery draft; remaining drafts at launch are offered individually for restoration.
- Code: upon resume, open files and the folder tree are immediately re-checked for changes on disk.
- Writer: a document with an associated file is saved during auto-save; an untitled, imported (.docx, .md, .txt), or read-only document is written to a recovery draft (.nxvdoc).
- Slides: a presentation with an associated file is saved during auto-save; an untitled or read-only presentation is written to a recovery draft.
- Sheets: auto-save saves a spreadsheet with an associated file without closing the cell currently being edited (with confirmed content); an untitled spreadsheet is written to Sheets' existing recovery copy and appears in the "Recovered" list on the startup screen.
- Sheets: scroll momentum stops when entering sleep; upon resume, file changes are checked and volatile formulas such as NOW() / TODAY() are recalculated.
- Paint: a PNG document is saved in place during auto-save (written to a temporary file first, then replaced); an untitled image or imported JPEG/BMP is written to a recovery draft (PNG).
- Paint: auto-save does not wait while a brush stroke, shape drawing, or floating selection is in progress and does not touch them; it writes the pixels committed at that moment. Pending tool preferences are also written.
- 3D Modeler: a scene with an associated file is saved during auto-save; an untitled or sample scene is written to a recovery draft (keeping texture paths absolute); paused during dragging or transformation.
- All document apps (Text Editor, Code, Writer, Sheets, Slides, Paint, 3D Modeler) report unsaved changes to the system; Exit / Restart Nexvyn OS recognizes these windows.
- The "— Edited" mark in window titles is shown consistently across all document apps, including restored drafts.
- Notes, Sticky Notes, Reminders, Calendar, and Contacts: pending saves with a short delay are immediately written to disk during auto-save, when entering sleep, and before shutdown.
- Sticky Notes: window position is also saved at the same time.
- Notes: upon resume, "Today" / "Yesterday" groups are rebuilt.
- Calendar: upon resume, today's date, "now" line, mini calendar, and Upcoming list are refreshed; re-read if the event file was modified elsewhere.
- Video Player: when Nexvyn OS moves to the background (HOME menu, sleep), video is paused, controls remain visible; position and settings are saved.
- Video Player: playback position is saved during auto-save.
- Video Player: "Retry" button added to the screen for streams that fail to open or lose connection.
- IPTV: channel is paused when going to the background; upon resume, reconnects to live broadcast (remains paused if the user paused it manually); pending state is saved.
- Radio: broadcast continues in the background as before; upon resume, station or country lists that failed to load due to lack of connection automatically reload.
- Music: playback continues in the background as before; pending volume changes are saved when entering sleep, time zone and date labels are refreshed upon resume.
- Photos: slideshow is paused when going to the background; upon resume, newly added images are searched for and date sections are refreshed; pending thumbnail size setting is saved.
- Terminal: a running command (copying, downloading) is reported as unsaved work when exiting Nexvyn OS.

### App Guard (17)

- Apps on the SD card cannot read or write Nexvyn OS's own data (`sdmc:/NexvynOS/System`: settings, users and PIN, permissions, logs, Overlay; except extension folders `Library` and `Fonts`), even with the `files` permission
- Likewise, `Application Support` and `Caches` folders of other apps are locked: Browser cookies, history, and saved passwords, AI Chat keys, FTP passwords, Tube account, and words learned by the keyboard are no longer accessible to any third-party app

- Paths are compared as the SD card compares them (case-insensitive, `..`, `\`, trailing dot): the sandbox cannot be bypassed with an alternate spelling of the same folder; a rejected protected path is written once to the app's log as `protected path: ...`
- The new App Guard scanner reads the package's text sources (`.lua`, `.js`, `.py`, `.nut`, `.c`, `.java`, `.json`) with a size limit and on its own background thread, assigning each finding a level (note / review / dangerous) and a short reason
- The scan catches: paths to private data or console keys ("can send your data" with network permission = Dangerous), custom firmware / bootloader / `.nro` files, downloaded-and-executed code, code decoded from an encoded blob, Lua `string.dump`, harvesting typed input in a network-enabled app, raw sockets to unusual ports in CPython apps, and permissions never used by code

- App Store's permission sheet states "Reviewed by Nexvyn OS" for apps in the store's own catalog; every download is scanned with the same rules before install, and dangerous ones await "Install Anyway" confirmation
- The App Store catalog can carry an optional `security.blocklist` (sha256 + reason): listed packages appear as Dangerous; since Nexvyn OS keeps the hash of the package each app was installed from in `Config/appguard.json`, installed apps also match
- The blocklist only warns: App Guard does not shut down, uninstall, or block any app, and nothing from the internet can force this; the decision belongs to the user
- At the top of System Settings > Privacy & Permissions, a new App Guard section: "Scan apps before installing" toggle (`appguard.scanBeforeInstall`, on by default)

### Post-camera freeze fix (fixfreeze) (3)

- libnx frees the memory of a transfer memory (IR camera work buffer, six-axis sensor buffer) as soon as its handle is closed; if the service is still holding the memory (the emulator's stub `irs` service never closes the handle received from `RunImageTransferProcessor`, which can also happen on console while stopping is in progress), the kernel keeps this range borrowed (locked). When the heap reallocated the same memory, GPU buffers (`SetMemoryAttribute`) and IPC buffers (`SendSyncRequest`) failed with `InvalidCurrentMemory` and the system froze. Now `__libnx_free` checks with `svcQueryMemory` before returning memory to the heap; blocks still held by the service remain outside the heap, and a warning is logged to the system log
- Fixed a freeze in the PC test environment when switching to other apps after opening and closing Camera; the full UI smoke test (74 apps) finishes without crashes or script errors
- Developers: `tools/ui_smoke.py` adds optional system apps during testing (`enableall`), so 37 apps have their own windows tested instead of their App Market page; `apps.optionalEnabled` setting reverts to its original state once testing finishes

### 3D playtest crash, Switch Tools folder, and language-tracking desktop folders (fix11) (14)

- **Root cause (g3d GPU back end):** When clicking **Play** in a 3D project within Game Engine, the editor's 3D scene and the playtest window are rendered in the same frame. Because the playtest viewport is larger, g3d's offscreen texture is enlarged, and the old texture (which the editor had copied to the screen in that same frame) and depth renderbuffer were deleted before the frame was presented to the screen. The GPU driver (Switch nouveau) was still holding them in that frame's push buffer and freed them a second time inside `SDL_RenderPresent` (`nouveau_bo_del` → `free` → double free). The emulator crashed without logs (0xC0000005 in HostMappedUnsafe); the console suffered from the same issue. 2D Platformer was unaffected because the 2D editor does not use g3d.
- g3d now deletes GL objects it no longer uses (buffers of dead meshes, outgrown offscreen textures, old depth buffers) one frame later: the new `gfx::frameIndex()` advances every frame, and no object is deleted before the frame in which it was used is presented. An expanding target allocates a new renderbuffer instead of resizing the depth buffer currently in use.
- In the PC test environment, 3D Runner, 3D Racing, 3D Collect, and Empty 3D templates along with Robot Run and Golden Island samples were opened and playtested from Game Engine: all work properly. `lua_check --workshop` runs every genre across every theme (78 packages) with no errors.
- **Runner style:** When the auto-running player collided with a box (solid) in their lane, they would get stuck there indefinitely. Now, pressing against an obstacle ahead for a moment counts as a hit: a life is lost (as per the templates' "don't hit boxes!" warning), and the player bounces back one step, allowing them to dodge or jump. Grazing an obstacle from the side does not take away lives.
- After a fresh install, only YamaNX was in the **Switch Tools** folder: other tools are optional built-in apps installed when selecting **Get** from the App Market, but their shortcuts were never added to the folder. Now, when an app is installed or an optional app is added, its shortcut is added to its respective default desktop folder (Games, Tools, Office, Media, Switch Tools); if the folder does not exist, it is not recreated. Built-in apps are placed according to `defaultGroups()` lists, and package-installed apps according to the app.json `category` field (`switch` → Switch Tools, `games` → Games, `utilities` → Tools, `productivity` → Office, `media` → Media). A second shortcut in a folder is not created for an app that already has a shortcut on the desktop.
- When an app is uninstalled or an optional app is removed, the system-created shortcut is also removed from the folder; it is restored when re-added.
- A shortcut deleted by the user does not return: deleted shortcuts are kept in the `desktop.linksRemoved` setting (folder type → app IDs), and each folder's known apps are stored in `desktop.folderApps`.
- On previously set up desktops, shortcuts for tools that are installed but missing from the folder are added once at startup (`desktop.folderSyncV1`).
- Multiple shortcuts pointing to the same app within the same folder (e.g., "Cheat Manager" and "Hile Yöneticisi", both `cheats`) are deduplicated to one; the remaining shortcut takes the name in the current language. User-renamed copies are preserved, and shortcuts with `arg` are untouched.
- Folders created during installation previously remained in the installation language (English "Office, Tools, Games, Media, Switch Tools" in a Japanese UI; Turkish folders in an English UI on an old SD card). Now, when the UI language changes and once at startup, system-created folders (identified not by their names, but by the `.nxvfolder` marker and icon) take their names in the new language.
- `.nxvfolder` now also stores the system-assigned name (`"sysName"`); written when the system creates or renames a folder. Regardless of where the user renames the folder (Desktop, Files, Terminal, FTP), since the name no longer matches `sysName`, the flag is considered cleared and the folder keeps the user-given name. For pre-1.0.0 markers lacking a name, if the folder name is a default name in one of the 8 supported languages, it is considered a system name (new `i18n::translations()`).
- System shortcuts on the desktop and in these folders (`.nxvlink`, `{"app": id}` only) also take the app's name in the new language; they also store `"sysName"`, leaving user-renamed ones unchanged. Desktop icons preserve their grid positions (`desktop.layout`) when renamed.
- Name collisions are safe: a user file or folder is never overwritten. If a system folder of the same type exists under the target name, contents are moved there (system shortcuts to the same app are dropped, everything else retains its name or takes an available name) and the emptied folder is deleted; if something else exists, the folder retains its old name.
